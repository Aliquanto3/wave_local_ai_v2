| 🔴 | code | 3 | `src/wave_local_ai_v2/__init__.py:383` | `tokens_in_total = counted[0]["tokens_evaluated"]` is **one** repetition's prompt-token count while `tokens_out_total` (`:374-382`) sums **all N**. `cache_prompt: False` forces a full prefill on every repetition, so the counted set really evaluated `N × tokens_evaluated`. The two halves of `total_tokens` (`:385-389`) therefore span different windows, while `cost_total` and `energy_kwh` span the whole set. On the phase-3 live row (`phase-3.md:79-81`) the denominator is 1490+640=2130 instead of 5×1490+640=8090, so the published `cost_per_million_tokens` 0.2411 is 3.8× the true 0.0635. Fixed: both totals now go through `cost.total_or_none` over `counted` (`__init__.py:369-377`). Live re-run confirms `tokens_in_total=7450` (5×1490) and `cost_per_million_tokens=0.0617` (`phase-3.md:67-92`). |
| 🔴 | fit | 3 | `src/wave_local_ai_v2/quality_cli.py:386` | `list_price_per_million_tokens = cost_total / total_tokens * 1_000_000` publishes a rate derived **from** the cost, not the list price the cost was derived from — it is byte-identical to `cost_per_million_tokens` on the same row (`:405-407`). The table's actual inputs (`input_per_million` 0.15, `output_per_million` 0.60) never reach the row, so the story's reader "recomputing a published cost a year later" gets a circular figure and cannot tell a wrong row from a moved price. Also deviates from `phase-3.md:137` ("`list_price_*` populated from the same table entry"). Fixed: `list_price_input_per_million` and `list_price_output_per_million` added to both `REQUIRED_FIELDS` kinds (`row_contract.py:106-107,182-183`), populated from the table entry (`quality_cli.py:441-442`), null on local rows. The blended rate stays beside them, now derived through the guarded `cost.cost_per_million_tokens`. `SCHEMA_VERSION` `"5"` → `"6"`. |
| 🟡 | code | 3 | `src/wave_local_ai_v2/quality_cli.py:386` | The same expression divides by `total_tokens` unguarded. `total_tokens == 0` (an empty batch, or every `prompt_tokens` null with zero completion tokens) raises `ZeroDivisionError` mid-run, after the local rows are already on disk — while `cost.cost_per_million_tokens` two lines below exists precisely to return `None` in that case.
