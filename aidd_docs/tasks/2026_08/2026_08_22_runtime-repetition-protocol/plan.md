## Decisions

| Decision                                                                                                                                                                                                       | Why                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The seed is pinned **in the request body**, not by a server flag; `server.build_flags` stays byte-for-byte the validated baseline command.                                                                     | Probed: the `/completion` body honours `seed` on b10537. This is the pattern `quality_cli.LOCAL_SAMPLING` already uses for exactly this reason. It satisfies story 6 without departing from `context_input/baseline_qwen36.md`, so the republished rows stay comparable to the two curated rows that carry the project's headline throughput.                                 |
| Warm-up isolation is **per-request `cache_prompt: false`**, not slot erase.                                                                                                                                    | Slot erase returns 501 unless `--slot-save-path` is added to the launch command, which would change the validated flag set. `cache_prompt: false` forces a full prefill per repetition with no flag change, and reproduces exactly the condition the two reference rows were measured under: one fresh server, one full, uncached prefill.                                    |
| `truncated_max_tokens` is defined on the runtime path but **unreachable by construction**; only `empty`, `unparseable` and `truncated_context` fail a repetition.                                               | The runtime harness *chooses* `max_tokens=128` as its measurement budget, so `stop_type: "limit"` is the intended stop of every healthy run. Treating it as truncation would fail every row. The cap stays disclosed on the row (`max_tokens`, Methodology 3) and each repetition records `stop_type` and `tokens_predicted`, so a short generation is visible, not hidden. |
| `SCHEMA_VERSION` moves `"1"` → `"2"`.                                                                                                                                                                          | The runtime row's shape changes incompatibly (a scalar `gen_tok_per_s` becomes a median over a repetition set). Leaving both shapes at version 1 defeats the field's purpose under Methodology 19. The constant is shared with quality rows, so those move too; splitting into per-kind versions is out of scope.                                                             |
| Energy is **one CodeCarbon measurement spanning the counted repetitions and the cooldowns between them**; the warm-up runs outside it.                                                                         | The warm-up is excluded from N, so it must be excluded from the energy window too. The cooldowns sit inside the counted span and cannot be carved out of a single tracker, so the row's aggregation label says so rather than implying the figure covers generation alone.                                                                                                    |
