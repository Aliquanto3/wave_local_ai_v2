## Decisions

<!-- Architecture-magnitude only, one you'd regret reversing. Omit if none qualify. -->

| Decision   | Why   |
| ---------- | ----- |
| A new console entry (`wave-local-ai-v2-judge-probe` → `judge_probe.py:main`), not a flag on `wave-local-ai-v2-quality`. | The smaller of the two, measured on the diff rather than on the number of new files. `quality_cli.py` is shaped around `CLASSIFICATION_TASK_SUITE` at five call sites (`_run_local_suite`, `_run_cloud_batch`, `_resume_skip_reason`, `_score_and_write`, and the accuracy print), all of which a probe flag would have to branch: a different item shape with no labels, no accuracy, a judge stage after generation, a different output path and a one-item cloud batch. A flag would rewrite the shipped quality path to carry a mode it never runs in; a separate entry adds one `[project.scripts]` line and touches the quality CLI only where code is *moved out* of it. The story's own "Code it changes" list names `judge_probe.py`, `settings.py` and the README, and does not name `quality_cli.py`. |
| The runner writes directly into the tracked `judge-probe-reference.jsonl`; there is no untracked live probe store beside it. | The story and the epic both name that file as where the probe's rows go, and the probe is a deliberate one-off proof rather than a per-machine benchmark that reruns. The tradeoff is real and is stated in the README section phase 3 writes: this is the **one** reference file a CLI writes to, breaking the "no CLI ever writes to a reference file" rule the results README states for the other two, and a re-run under a fresh `run_id` appends a second generation of rows rather than replacing the first. The operator's reset is `git checkout -- aidd_docs/results/judge-probe-reference.jsonl`, named in phase 2's teardown. `.gitignore` already re-includes `*-reference.jsonl`, so no ignore rule changes. |
| The **suite-level** `agreement`, `judged_headline_score` and `judged_headline_excluded_n` are published on every two-judge row, replacing the per-item figures `judge.judge_item` returns. | Kappa over one item is undefined by construction — `agreement.cohens_kappa` returns null with `insufficient_items`, as its own docstring states — so a per-item block cannot carry the "real agreement figure" the story's acceptance requires. Publishing the batch figure on every row of the batch is the pattern `suite_accuracy`, `failure_counts`, `language_breakdown` and `verdict` already follow. Nothing is lost: each row keeps its own two judge scores under `judges` and its own `contested` marking, so any other statistic is recomputable from the published rows alone. The single-judge row is untouched — it carries `agreement: null` and the flag. |
| A probe row's `verdict` is an explicitly constructed `not_comparable` block naming why, not the output of `verdict.quality_verdict`. | `quality_verdict` decides by comparing `predicted_label` across runs. The probe has no labels: every `predicted_label` is `null`, so a second probe run compared against the first would find every item identical and publish `reproduced` — a reproduction claim about labels that do not exist. The honest block says there is nothing to reproduce against: an open-ended output's judged score is not a label, and the judge replies are not assumed reproducible (`judge.py`'s own docstring records Mistral failing to reproduce one reply at temperature 0 with a pinned seed). |
| Three functions move out of `quality_cli.py` into modules both CLIs import (`resume_skip_reason` → `results.py`, `local_batch_fields` and `cloud_batch_fields` → a new `quality_rows.py`), rather than being re-implemented in `judge_probe.py`. | The two batch-field builders construct ~35 contract-governed energy/emissions/cost keys each; a second copy would be a parallel declaration of the row contract's cost rules, and the first divergence between the copies would publish two different cost derivations under one schema version. `resume_skip_reason` is the same "never re-pay, never duplicate" rule the story requires the probe to reuse, parameterised on the batch's expected item count instead of reading `len(CLASSIFICATION_TASK_SUITE)`. Behaviour-preserving moves: the quality CLI's own tests keep passing untouched. |
| The probe **refuses** to run when either judge is unavailable, unlike the quality CLI, which skips an unavailable cloud provider and continues. | The quality CLI's cloud providers are subjects: losing one costs a comparison column. The probe's judges are the thing being proven, and a probe run that quietly produced ten single-judge rows because a key was missing would publish the honest-flag path as if it were the two-judge path. A missing key, a provider absent from `QUALITY_PROVIDERS`, or a failed pre-flight is one stderr line and exit 1, before any generation is paid for. |
| The subject's own text is published under a non-required `subject_output` key; `predicted_label` stays `null`. | The row must be inspectable — the epic's Success Evidence reads scores and prompts "off the row, not off the template source" — and the judge block carries only the judges' raw replies, never the text they judged. `predicted_label` means a label drawn from a closed set (`scoring.normalize_label`); putting free-form prose there would make the field mean two different things across `quality.jsonl` and this file. The extra-key mechanism is the one Google rows already use for `model_version`/`api_version` (`_score_and_write`'s `extra_row_fields`), so no contract change and no schema bump. |
| The probe items go through `suite_gate.gate_suite`, and every probe row publishes `indicative: true` naming its sub-20 item count. | The story requires the probe to sit below Methodology 4's 20-item gate *deliberately* and to say so. Running the gate makes the rows say it themselves rather than leaving it to the README: the gate marks an under-sized set indicative rather than refusing it, and it still refuses an item whose language/provenance/contamination declaration is missing or self-inconsistent — which is worth having on a hand-written item set. |
